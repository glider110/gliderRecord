## Free、Pro 和 Max 实际重置的是什么

想看懂 Claude 限制，最有效的办法不是继续追一个“每天到底多少 token”的神秘数字，而是回到 Anthropic 当前真正公开的套餐合同。

对 **Free Claude** 来说，Anthropic 当前写得最明确的是：它有一个 **基于 session 的使用限制** ，并且 **每 5 小时重置一次** 。但 Anthropic 并没有承诺一个稳定公开的消息数，也没有承诺一个稳定公开的 token 数。官方同时也明确说过，Free 的实际可用量会受当前负载影响，不同功能消耗速度也不一样。所以你看到别人说“我今天还能发多少条”，那通常更像是个人体感或某个时间窗口里的经验值，而不是你可以拿来当合同的公开数字。

对 **Claude Pro** 来说，规则更宽，但并没有变得更“整齐”。Anthropic 现在的公开表述是：Pro 在高峰时段每个 session 至少有 **Free 的 5 倍使用量** ，仍然按 **5 小时重置** ，同时还有一个 **按周计算的 all-model 限制** 。这个周限制很重要，因为很多第三方页面只盯着短期体验，却不提醒你：有些套餐看起来单次 session 很够用，但如果你连续几天都在重负载使用，真正先撞上的可能是周限制，而不是当天那一段时间的 session 余量。

对 **Claude Max** 来说，Anthropic 公开的是价格和相对倍率，不是一个漂亮的“日配额表”。Max 5x 当前是 **100 美元 / 月** ，Max 20x 是 **200 美元 / 月** 。官方说这两个档位分别给你 **Pro 的 5 倍或 20 倍 session 使用量** ，同时也仍然有 **周限制** 。这也是为什么 Max 很容易被误解。它确实比 Pro 大很多，但“大很多”和“没有限制”不是一回事。

把三档套餐压缩成一句人话，大概是这样：

| 套餐 | 当前公开说法 | 真正重置什么 | 哪些部分仍然可变 | 你应该怎么理解 |
| --- | --- | --- | --- | --- |
| Free | 基于 session 的使用限制 | 5 小时 session 重置 | 当前负载、对话长度、文件、工具和功能都会改变体感容量 | 适合普通消费级使用，不适合拿来期待稳定重负载 |
| Pro | 高峰期每个 session 至少是 Free 的 5 倍 | 5 小时 session 重置 + 周限制 | 实际可用量仍取决于工作负载 | 更适合经常重度使用，但仍不是固定日额度 |
| Max | 每个 session 是 Pro 的 5 倍或 20 倍 | 更大的 session 余量 + 周限制 | 仍然是动态系统，而且官方保留额外限制空间 | 适合高强度用户，但不是无限量 |

还有一个经常被忽略的点，会直接改变你的体感：Anthropic 现在明确说， **claude.ai、Claude Code 和 Claude Desktop 会共享同一池使用量** 。所以如果你白天已经在网页端做了很多长对话，晚上再去 Claude Code 里干重活，就很容易觉得“今天额度怎么掉得这么快”。很多时候，这不是系统突然变了，而是你在多个表面同时消耗了同一池资源。

## 为什么 Anthropic 不给一个固定的每日 token 数

很多人会追这个数字，不是因为他们想得不对，而是因为大量 API 产品都在训练我们用这种方式理解额度。问题在于，Claude 面向消费者的 Free、Pro、Max 套餐，目前公开合同就不是这样设计的。

Anthropic 在帮助页面里反复强调的是 **可变使用量** 。真正影响你还能用多久的，不只是“发了多少轮”，而是消息长短、附件大小、当前对话累积了多少上下文、你用了什么模型、用了哪些工具、系统当前处在什么负载状态。也正因为如此，任何一个第三方页面如果很自信地告诉你“Claude 每天就是固定多少 token”，都应该谨慎看待。它很可能把某个时期的观察、某个语言版本里的规划性数字，或者社区里的体感，包装成了一个稳定公开合同。

Anthropic 自己的页面也会制造一点表面上的混乱。比如官方的 web search 帮助页会说， **Free 账户的 web search 和 web fetch 存在 daily limits** 。这句话是真的，但它并不等于“Anthropic 给所有 Free、Pro、Max 用户都公开了一个统一的每日 token 上限”。更准确的理解方式是：这是 **某个功能表面** 的日级限制语言，而不是整个消费级 Claude 计划的统一配额语言。如果你在 Free 上大量使用网页搜索、长链接抓取，体感上的“日限制”会更明显，但这依然不能被偷换成一张所有使用行为都通用的每日 token 表。

所以，真正更有用的问题，不是“Claude 一天到底给我多少 token”，而是“我当前这类使用，到底在消耗哪一种容量”。Anthropic 当前公开的消费者答案，本质上是 **重置规则 + 动态工作负载** ，不是 **稳定 token 表** 。

这套理解方式听起来没有“固定数字”那么爽快，但它更接近你真正面对的产品现实。你如果是轻负载、短对话，Free 可能比你以为的更能撑；你如果在 Pro 或 Max 上做长对话、传大文件、跨多个表面高强度使用，它也可能比你想象中更快见底。问题不是 Anthropic 把数字藏起来了，而是它公开的核心合同本来就不是“一个数字解释全部”。

## 使用限制、上下文窗口和 API 计费不是一回事

“token limit” 这个说法之所以总是把人带偏，是因为它在现实里至少会指向三套完全不同的系统。

第一套是 **消费者套餐的使用限制** 。这就是大多数人在问 Claude 为什么停下来的时候，真正碰到的那套系统。它对应的是 5 小时重置、周限制、跨 claude.ai / Claude Code / Claude Desktop 的共享使用，以及不同套餐之间相对而不是绝对的容量差异。它回答的是：“我还能继续用多久，什么时候该等重置、开额外用量或升级？”

第二套是 **上下文窗口** 。它回答的是另外一个问题：“Claude 一次能装下多少文本上下文？” Anthropic 当前帮助页说，付费 Claude 套餐通常是 **200K 上下文窗口** 。这并不等于你一天能用 200K token，也不等于你今天一定还能继续用到 200K。上下文窗口描述的是一次会话里模型能处理多少上下文，而不是你今天还有多少使用量。

第三套是 **API 计费和 API 速率限制** 。这是你在 Claude Console 或 API key 语境里才该使用的理解框架。API 使用量看的是 token 定价、速率桶和消费上限，不是消费者套餐里的 5 小时重置或周限制。所以如果你真正的问题是“发多少 token 会收费”“API 还能打多少请求”“Console 额度怎么算”，那就已经不是 Free / Pro / Max 这篇文章的主问题了。

这三套东西可以这样记：

| 系统 | 它真正衡量什么 | 当前公开合同是什么 | 最容易犯的错 |
| --- | --- | --- | --- |
| 消费者使用限制 | 你还有多少套餐使用量 | 5 小时重置、周限制、动态容量 | 把它当成一张固定每日 token 表 |
| 上下文窗口 | Claude 一次能装多少上下文 | 付费套餐通常是 200K | 把上下文大小当成今天的可用额度 |
| API 计费与速率限制 | API 请求如何收费和限流 | token 定价、速率限制、消费控制 | 以为 Pro / Max 自带 API 预算 |

如果你的真实问题其实是编码工作流里的消耗，而不是一般消费者聊天，应该直接去看 [Claude Code 用量指南](https://blog.laozhang.ai/zh/posts/claude-code-rate-limit) 。如果你真正想问的是 API key、Console credits 或 API 免费额度，则应该去看 [Claude API 免费额度指南](https://blog.laozhang.ai/zh/posts/claude-api-key-free-tier) 。把这三套系统先拆开，你后面的判断会清楚很多。

## 撞到限制后，下一步怎么选

一旦你先确认了自己在哪套系统里，下一步其实就没那么难了。

**如果你在 Free 上撞到限制，先看工作负载，不要先看 folklore 配额。** 长对话、大附件、搜索型提示词和长链接抓取，都会让 Free 看起来比普通文本聊天小得多。对大多数人来说，第一步通常是等下一次 5 小时重置、缩短当前会话、减少一次性让 Claude 处理的内容。如果这种情况开始反复打断正常工作，那真正的信号不是“我还没找到正确的每日数字”，而是 Free 已经不太匹配你的使用模式了。

**如果你在 Pro 上撞到限制，先判断这是不是持续性中断。** Pro 对很多认真使用 Claude 的用户来说，仍然是最合理的默认答案。真正的升级信号，不是“我今天撞到过一次限制”，而是“5 小时重置和周限制已经开始稳定打断有价值的工作”。Anthropic 现在也给付费计划提供了 **extra usage** 。如果你的高强度使用是阶段性爆发，而不是天天如此，那么 Pro 加额外用量，很多时候会比全年背着 Max 更划算。

**如果你在 Max 上仍然频繁撞到限制，不要第一反应就认定是官方失约。** Max 本来就只是更大的消费级容量，不是无限量。很多时候更简单的解释反而更成立：这一周跨多个表面的使用异常重、对话比平时更长、文件更多、功能更复杂，或者你其实在做的是更像自动化工作负载的事情，本来就更适合 API 计费而不是消费级订阅。

**如果你真正的问题其实是 Claude Code，请直接切到兄弟页。** Anthropic 说付费套餐下的 Claude 与 Claude Code 会共享使用量，但 Claude Code 里真正影响你判断的，还包括 `/status` 、 `/cost` 、上下文增长和认证路径。所以如果你是编码工作流里的“怎么又见底了”，请直接看 [Claude Code 用量指南](https://blog.laozhang.ai/zh/posts/claude-code-rate-limit) ；如果你想比较重度编码场景里 Pro 和 Max，到底哪档更值，则看 [Claude Code Pro vs Max 详解](https://blog.laozhang.ai/zh/posts/claude-code-pro-vs-max) 。

**如果你真正的问题是 API token，就不要再用消费者套餐语言看它。** Pro 和 Max 不是 API 预算。如果你需要明确的成本、吞吐和开发者合同，就直接按 Console 与 API 的逻辑来理解，这也是 [Claude API 免费额度指南](https://blog.laozhang.ai/zh/posts/claude-api-key-free-tier) 更适合你的原因。

一句话总结： **当前套餐适合你，就等重置；只是偶尔爆发，就开额外用量；已经稳定打断工作，就升级；真正是另一套系统的问题，就换到对应兄弟页。**

## 常见问题

**Claude 有“每日限制”吗？**

有些功能表面，尤其是 Free 的 web search，会使用日级限制语言。但 Anthropic 目前并没有公开一个适用于 Free、Pro、Max 的统一每日 token 数。核心公开合同仍然是 5 小时重置、周限制和动态容量。

**到底什么东西每 5 小时重置？**

Anthropic 当前 Free 和 Pro 帮助页里讲得最明确的是 **基于 session 的使用限制** 每 5 小时重置。对大多数读者来说，这才是最值得先记住的短周期规则。与此同时，Pro 和 Max 还存在周限制，所以只盯一个 session 并不够。

**Claude Max 是不是无限量？**

不是。Max 会把容量拉高很多，但 Anthropic 仍然明确写了周限制，并保留额外限制空间。更准确的理解是“更大的消费者容量”，不是“没有上限”。

**网页搜索会算进 Claude 的限制里吗？**

会。Anthropic 的 web search 帮助页明确说，Free 账户的 web search 和 web fetch 会消耗该功能表面的容量。如果你觉得 Free 比想象中更快见底，而你又大量在跑搜索和抓链接，这很可能就是原因之一。

**上下文窗口是不是就等于 Claude 每日额度？**

不是。上下文窗口描述的是 Claude 一次能装下多少文本，上下文多大；使用限制描述的是你今天或这一段时间里还能继续用多少套餐容量。它们会互相影响体感，但不是同一个计量器。

**如果我其实在问 Claude Code 或 API token 怎么办？**

那这篇文章只负责先把大方向纠正回来。编码工作流里的共享用量、 `/status` 、 `/cost` 和套餐判断，请看 [Claude Code 用量指南](https://blog.laozhang.ai/zh/posts/claude-code-rate-limit) ；API、Console credits 和开发者计费，请看 [Claude API 免费额度指南](https://blog.laozhang.ai/zh/posts/claude-api-key-free-tier) 。

## 结论

“Claude token limit per day” 这个问法，最容易误导人的地方，不是它错得离谱，而是它把几套不同系统压成了一个问题。对消费者 Free、Pro、Max 套餐来说，更接近现实的答案不是一个固定数字，而是 **重置规则 + 动态工作负载 + 正确分流** 。

如果你只记三件事，记这三件就够了： **5 小时重置比 folklore 配额更重要，周限制比大多数人想象中更重要，而“token limit” 很多时候其实是在问另一套系统。** 把这三层先拆开，Claude 当前的限制和升级路径就会清楚很多。
